# HAPI Companion v0.4.0

Status: deployment candidate. This version has not been published as a stable update.

V0.4 adds an optional Android notification channel. A small Mobile Relay runs beside the Hub, consumes one durable SSE stream, applies the same conversation, keyword, duration and quiet-hour rules as the Mac, posts a fixed non-sensitive notification through ntfy, persists delivery, and explicitly ACKs the Hub. Delivery continues while the controlling Mac is asleep.

The Mac “声音与设置” tab now pairs the Relay, creates a one-phone subscription QR/copy target, sends a real-session test, activates delivery, syncs rules, pauses, repairs and removes the phone. Notification payloads exclude session titles and AI response bodies; tapping opens the exact HAPI PWA session.

Local candidate evidence:

- 67 macOS tests pass and the Release app builds for arm64 and x86_64;
- 84 Relay tests pass, including activation cleanup, strict sequence handling, provider/Hub failures, request timeouts, restart replay and configuration rotation;
- fake-provider and self-contained Linux x64 package smoke tests pass;
- `integrations/hapi/hapi-companion.patch` is unchanged, so the updater patch pin does not change.

Stable publication remains gated on production VM/TLS approval, real OPPO locked-screen/VPN-off acceptance, restart/upgrade/rollback evidence, signed Mac update packaging, review and canonical merge. See the [V0.4 specification](../specs/V0_4_ANDROID_NOTIFICATIONS.md) and [Relay runbook](../deployments/V0_4_MOBILE_RELAY_RUNBOOK.md).
