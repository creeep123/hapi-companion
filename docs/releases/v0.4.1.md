# HAPI Companion v0.4.1

Status: production acceptance candidate. This version has not been published as a stable Mac update.

V0.4.1 lets an activated Android receiver use the same HAPI event title and reply summary shown in Mac notifications. Fixed, non-sensitive text remains the default. Enabling the new mode requires a separate privacy confirmation because public ntfy.sh receives those fields and may cache them; disabling affects future notifications and survives synchronization conflicts or app restarts.

The Mac verifies Relay capability before offering the mode. The Relay accepts only `fixed` or `eventPreview`, cleans control characters and malformed Unicode, applies UTF-8-safe title and body limits, rebuilds the exact-session click URL, and does not store notification content in state, delivery history, health or logs. Test notifications remain fixed and non-sensitive.

Candidate gates:

- all macOS and Relay tests, typecheck, fake-provider smoke and self-contained Linux x64 package smoke pass;
- independent product, architecture and operations review has no P0/P1 finding;
- artifacts are rebuilt from a clean pushed commit and their hashes recorded;
- production Relay upgrade/rollback and native Mac install/reconnect preserve pairing and settings;
- one real OPPO completion notification shows the expected Mac event title/summary and opens the exact HAPI PWA session.

The Hub patch is unchanged at its pinned SHA-256, so this release does not require an updater pin handoff. See the [V0.4 specification](../specs/V0_4_ANDROID_NOTIFICATIONS.md), [ADR 0005](../adr/0005-mobile-notification-relay.md) and [Relay runbook](../deployments/V0_4_MOBILE_RELAY_RUNBOOK.md).
