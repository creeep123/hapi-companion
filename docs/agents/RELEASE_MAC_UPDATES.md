# Publish signed Mac updates

Canonical code branch: main. Hosting: public GitHub Releases for immutable ZIPs; reviewed `updates/appcast.xml` on main via free jsDelivr GitHub CDN. No new account/billing or Hub deployment. Sparkle is pinned to 2.9.6 in project.yml.

1. Increment MARKETING_VERSION and CURRENT_PROJECT_VERSION (strictly increasing integer). Add release notes and acceptance criteria. Review through a scoped PR. Build only a clean pushed commit; record its SHA and later canonical merge.
2. Run `./scripts/package-release.sh VERSION`. It runs tests and a clean universal build; preserve dist artifacts. Inspect the normal bundle, version/build, Sparkle helpers/license, feed URL and signed-feed/pre-extraction policy. Run audio checks if assets changed.
3. Upload the immutable ZIP, patch/brand assets and SHA256SUMS to a prerelease candidate on the known build SHA. Never overwrite an already published archive. Re-download and verify SHA-256. The Hub patch is a compatibility artifact, not deployment authorization.
4. Use official Sparkle tools from its pinned distribution. The private Ed25519 key remains in login Keychain under account `io.github.creeep123.hapicompanion.updates`; never print/export it or store it in CI. `generate_keys --account ... -p` returns only the public verification key. Keep the private key safe: losing it in ad-hoc distribution can require a manual client bootstrap. Never casually rotate SUPublicEDKey.
5. Run `./scripts/prepare-appcast.sh VERSION /absolute/path/to/Sparkle/bin`. This requires the public release asset to exist, verifies its digest/size against the local ZIP, inserts its immutable GitHub API URL, and signs the final feed. The app requests octet-stream for downloads. Only public unauthenticated downloads are used.
6. Validate older-build -> newer signed archive with actual Sparkle installation/relaunch and Hub reconnection, preserving settings and rollback. Check failed feed/signature behavior and current-version UI. Temporary alternate feed/build overrides are acceptance-only and must be removed from the installed normal app.
7. Commit the staged `dist/vVERSION/appcast.xml` to `updates/appcast.xml` through review and merge to main. Do not hand-edit signed bytes without re-signing. Publish assets before exposing their feed.
8. Purge `https://purge.jsdelivr.net/gh/creeep123/hapi-companion@main/updates/appcast.xml`, then download the CDN feed and verify byte equality and Sparkle signature. Also use native URLSession (`swift scripts/check-update-feed.swift updates/appcast.xml`) because shell proxy success alone does not prove Mac app reachability. CDN propagation may lag; do not report completion from a purge acknowledgement alone.
9. Promote the accepted release to stable/latest, update README/Control Panel and deployment record (source SHA, tag, ZIP hash, runtime outcome, rollback). Confirm the installed app uses the canonical feed with no SUFeedURL user-default override. Other old Macs require one manual bootstrap.

GitHub Pages was evaluated but inherits an unrelated blog-domain redirect and is not used. Do not alter that domain or deploy updater code here. All server upgrade gates and patch pins remain owned by hapi-safe-updater.
